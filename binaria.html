6.2 Búsqueda binaria

La búsqueda binaria requiere que la colección esté ordenada. En cada paso se compara el objetivo con el elemento del medio y se descarta la mitad en la que no puede estar. Reduce el espacio de búsqueda de forma logarítmica.

Requisito indispensable Si la lista no está ordenada, el resultado puede ser incorrecto. Ordenar antes cuesta O(n log n); solo compensa si se hacen muchas búsquedas sobre la misma colección.

A Versión iterativa

def busqueda_binaria(lista, objetivo):
    """Lista debe estar ordenada de forma ascendente.
    Retorna el índice o -1."""
    izq, der = 0, len(lista) - 1
    while izq <= der:
        medio = (izq + der) // 2
        if lista[medio] == objetivo:
            return medio
        if lista[medio] < objetivo:
            izq = medio + 1
        else:
            der = medio - 1
    return -1
lista = [1, 3, 5, 7, 9, 11, 13]   objetivo = 9

izq=0, der=6, medio=3 → 7 < 9 → izq = 4
izq=4, der=6, medio=5 → 11 > 9 → der = 4
izq=4, der=4, medio=4 → 9 == 9 → encontrado

B Versión recursiva

def busqueda_binaria_rec(lista, objetivo, izq=0, der=None):
    if der is None:
        der = len(lista) - 1
    if izq > der:
        return -1
    medio = (izq + der) // 2
    if lista[medio] == objetivo:
        return medio
    if lista[medio] < objetivo:
        return busqueda_binaria_rec(lista, objetivo, medio + 1, der)
    return busqueda_binaria_rec(lista, objetivo, izq, medio - 1)

Misma complejidad temporal; usa O(log n) de espacio en la pila (la iterativa usa O(1)).

C Complejidad

CasoComparacionesComplejidad
Mejor (justo en el medio)1O(1)
Promedio / peor≈ log₂(n)O(log n)
Espacio (iterativa)—O(1)
Espacio (recursiva)—O(log n)

Para n = 1 000 000: secuencial hasta ~10⁶ comparaciones; binaria como máximo ~20.

D Variantes útiles

Límite inferior / superior (lower_bound / upper_bound)

Encontrar la primera posición donde se podría insertar el objetivo manteniendo el orden, o el primer elemento estrictamente mayor. Muy usadas en programación competitiva y en bisect de Python. 

import bisect

lista = [1, 3, 3, 3, 7, 9]
# Primera posición de 3
print(bisect.bisect_left(lista, 3))   # 1
# Posición después del último 3
print(bisect.bisect_right(lista, 3))  # 4

E Cuándo usarla

✅ Adecuada cuando

  • Los datos están (o se pueden mantener) ordenados
  • n es mediano o grande
  • Se hacen muchas búsquedas sobre la misma colección ordenada
  • Se necesita también localizar rangos (lower/upper bound)

Limitaciones

  • Requiere orden previo (costoso si los datos cambian mucho)
  • Acceso aleatorio eficiente (arreglos); en listas enlazadas no conviene
  • Para acceso “casi O(1)” con muchas actualizaciones, hash suele ser mejor
